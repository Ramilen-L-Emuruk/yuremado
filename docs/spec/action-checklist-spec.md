# 行動チェックリスト仕様書

> 本書は**現在の実装が行動チェックリストをどう出し分けるか**をまとめた仕様書。実コードと食い違う場合は実コードを正とする。
> 関連: [`quake-spec.md`](quake-spec.md) の用語「一次細分区域」と電文の `points` 構造、[`eew-spec.md`](eew-spec.md) の予想震度、[`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) の欠測保持。

## 1. 概要

強い揺れを検知したとき、地図の上に「いま取るべき行動」を出す。火の元・靴・出口といった、揺れた直後の数分で判断が要るものを並べる。

| 対応ファイル | 役割 |
|---|---|
| `src/hooks/useActionChecklist.ts` | 出す・畳む・消すの状態管理 |
| `src/utils/actionChecklistTrigger.ts` | 3 経路それぞれの閾値判定 |
| `src/utils/nearbyStations.ts` | 登録地点の周りの観測点を集める |
| `src/utils/actionChecklist.ts` | 表示する項目の静的データ |
| `src/components/ActionChecklist/` | 表示 |

主な値は次の 3 つ。意味はそれぞれの節で述べる。

| 定数 | 値 | 何を決めるか |
|---|---|---|
| `NEARBY_RADIUS_KM` | 30 | 登録地点の周りとみなす半径（§3） |
| `SUPPRESS_MS` | 1 時間 | 畳んだあとボタンを出しておく時間（§4） |
| `COLLAPSED_ACTION_COUNT` | 3 | 畳んだ帯で見せる項目数（§5） |

**この機能は「出るべきときに出ない」ことが最も重い。** 逆に余計に出る害は小さい。判定に迷うところはすべて「出す」側へ倒してある（本書で「倒す」と書いているのはすべてこの意味）。

## 2. 出す条件 — 3 つの経路

揺れを知る手段は状況で変わるため、どれか 1 つでも閾値に達したら出す。

| 経路 | 見るもの | いつ分かるか |
|---|---|---|
| EEW | 予想震度（区域単位） | 揺れる前 |
| 強震モニタ | 検知エンジンが確定した観測点のリアルタイム震度 | 揺れている最中 |
| 地震情報 | 気象庁が確定させた震度 | 揺れが収まった後 |

緊急地震速報が間に合わない直下型では、強震モニタが最初の手がかりになる。ただし検知の確定を待つぶん、生の観測値が閾値を超えた瞬間よりは遅れる。

閾値は設定の「出す最低震度」（`actionChecklistMinScale`・既定は震度5弱）。「行動チェックリスト」を切ると（`actionChecklistEnabled`）3 経路とも発火しない。入り切りは最低震度と別の値なので、切って入れ直しても最低震度は残る（2026-10-25 ユーザー承認）。

### 同時に成立したら緊急度の順

3 つは同時に成立しうる（発報中の EEW・揺れている観測値・直前の地震の確定情報）。上の表の順に見て**最初に成立したものを出す**。順序を決めないと最後に評価したものが勝ち、EEW が出ている最中に「強い揺れがありました」という過去形へ落ちる。

**EEW が複数あるときは最も深刻なものを選ぶ。** 受け取った順に見て最初の 1 件で打ち切ると、後から発生したより強い地震の予想を見落とす（連続する余震や、離れた 2 地域でほぼ同時に起きたときに実際に起こる）。

**地震情報も、判定する地震のうち最も深刻なものを選ぶ**（同じ震度なら一覧で上にある方、つまり地震の時刻が新しい方）。

決めたこと:

- 続報が届いた地震も判定し直す（2026-10-19 ユーザー選択「続報が届いた地震も見直す (推奨)」）
- 判定する地震を覚えておき、その中で最も深刻なものを出す（2026-10-20 に諮り、原文「進めて」）
- 判定するのは最後に電文が届いてから 1 時間以内の地震に限る（2026-10-20 に諮った案の文面。原文「推しで」）。届いた時刻は、この画面が気づいた時刻で測る（下）

**判定する地震は 2 段で決まる。**

1. **覚える** —— 地震は次のどちらかのときに「判定する地震」として覚え、気づいた時刻を控える。
   - 一覧の先頭（地震の時刻がいちばん新しい）に初めて来たとき
   - 続報が届いたとき（下の「続報の見分け方」）。先頭でなくても覚え、時刻を控え直す
2. **選ぶ** —— 再描画のたびに、覚えている地震のうち控えた時刻から 1 時間（`SUPPRESS_MS`）以内のものを見て、閾値に達した中から最も深刻なものを出す

続報を拾うのは、観測点が続報で後から加わるため。先頭の 1 件だけを見ていると、続報が届く前に別の地震が先頭へ来たとき、前の地震で加わった近所の点が判定されない。

先頭でない地震が**初めて現れただけ**では覚えない。起動時の履歴や「もっと見る」で古い地震がまとめて入るたびに、何日も前の地震の帯が出ることになるため。

**1 時間で区切るのは、何時間も前の地震の帯が開き直さないようにするため。** 寿命が尽きて消した地震の記録（§4「寿命」・20 件まで）は群発で押し出される。期限が無いと、より深刻な地震の帯が寿命で消えたあとに、震度の低い古い地震の帯が出る。長さは帯の寿命（§4「寿命」）とそろえた。1 時間は電文の発表時刻ではなく、**この画面が気づいた時刻**から測る。そのため起動した時点で一覧の先頭にある地震は、何時間前の地震でも起動から 1 時間は判定する。

期限の内側では判定し続ける。先頭の地震だけをその都度見ると、続報で出た古い地震の帯が、次の再描画で先頭の地震（もっと低い震度）に差し替わる。寿命が尽きて消した地震（§4「寿命」）は選ぶ前に外す。外さないと、それが最も深刻なとき出すのを弾かれ、閾値に達した別の地震まで出なくなる。取消表示中の地震カードも判定しない（§4「元の EEW・地震情報が取り消されたとき」）。

#### 続報の見分け方

地震カードは、その地震について受け取った電文を控えている（`sourceTelegrams`）。この控えのうち**最も新しい発表時刻と、その時刻の電文の通数**の組（以下「指紋」）が、前に見たときと変わったら続報とみなす。発表時刻は DMDATA 版では分単位なので、同じ分に届いた続報は通数で拾う。控えを持たないカードや発表時刻を読めないカードは、カードの `id` と、採用した電文の識別子（`telegramKey`）の組を指紋にする。

取消表示中の地震は、前に見た指紋を残しておく。取消のあと同じ地震が出し直されたとき、先頭でない位置でも続報として拾うため。ただし取消のカードが一覧に残るのは 10 秒（[`quake-spec.md`](quake-spec.md) §6.2）で、それを過ぎてから出し直されたものは初めて現れた地震として扱う。

**限界が 4 つある。**

- 古い地震の初報が新しい地震より後に届くと、その地震は先頭に来ないので、続報が届かなければ判定されない（先頭の 1 件だけを見ていた頃と同じ）
- 最も新しい電文と同じ分の古い電文が後から足されると、続報と取り違える。古い報として採用されなかった電文が届いたときも、指紋は変わるので 1 時間が延びる
- 出ている帯の地震が期限を過ぎたあと、期限内の別の地震が閾値に達していると、帯はそちらへ切り替わる（震度が低くても）。期限が切れたこと自体では判定し直さないので、切り替わるのは次に何かが届いたとき（新しい地震・続報・強震モニタの更新など）
- 1 時間を過ぎてから届いた続報は、そこから 1 時間また判定する。遅れて加わった観測点で閾値に達すれば帯が出る

### 返すのは「判定に使った範囲の最大震度」

3 経路とも、閾値に達したかどうかと同時に**その範囲での最大震度**を返す。真偽だけを返して表示側が震度を別に組み立てると、判定した範囲と表示する震度がずれる（自宅の区域で判定したのに全国の最大震度をバッジに出す、など）。

### 階級表に無い震度は見なかったことにする

電文の震度は、実地震テストシナリオの手書き JSON など型検査を通らない経路からも来る（`eew.ts` の `eewMaxScaleInfo` も同じ理由で実行時に弾いている）。階級表に無い値は判定にも表示にも使わない。結果として半径内の点が 1 つも残らなければ、§3 の規則どおり全国基準へ倒れる。

経路ごとの補足:

- **EEW** … 区域を持たない報がある。気象庁は電文全体の予測震度の下限が震度 4 以上になって初めて区域を並べる（[`eew-spec.md`](eew-spec.md) §4。実電文 4,651 通のうち 3,886 通が区域を持たない）。standard 版では、Yahoo の強震モニタ（震源情報）で先に検知した報も、後から届く P2PQuake が区域を補うまで区域を持たない（同 §3）。区域を持たない報の扱いは、自宅の区域を引けるかと報の種類で分かれる
  - **自宅の区域を引けて、報が区域を持つ** … 自宅の区域の予想震度で判定する
  - **自宅の区域を引けて、報が区域を持たない** … **この経路を使わない**（2026-10-22 ユーザー承認。選ばれた選択肢は「区域が無ければ使わない」）。電文全体の最大予想震度で判定すると、遠くの地震でも自宅に帯が出るため。自前の予測震度で埋めることもしない —— 自宅に向けて「強い揺れが来ます」を自前の予想で出すことになり、気象庁 FAQ の「個別地点の震度の予想を利用者に提供」に当たりうる（[`forecast-computation-audit.md`](../forecast-computation-audit.md)）。この間は強震モニタと地震情報の経路で拾う。代わりに、standard 版の初報では区域が届くまで数秒遅れる
  - **「非常に強い揺れを検知・最大予測震度のみ」の報** … 区域を持たないが、検知した観測点（仮の震央）が自宅から 30 km 以内なら電文の最大予測震度で出す（2026-10-22 ユーザー承認。選ばれた選択肢は「検知点から 30km」。[`forecast-computation-audit.md`](../forecast-computation-audit.md) の 15）
  - **自宅の区域を引けない（地点が無い・区域名を引けない）** … 全国基準で判定する
- **強震モニタ** … 見るのは**検知エンジンが確定した揺れのメンバー観測点だけ**（下記「なぜ検知エンジンを通すか」）。値は**欠測を直前値で埋めた保持値**（[`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) §8）。生値だと強く揺れている最中の単発の欠測で閾値に達した瞬間を取りこぼす。加えて**震度0 は閾値がいくつであっても対象にしない** —— 強震モニタでは震度0 と震度1 の階級値が同じ（どちらも 10）で、設定は震度1 まで下げられる。階級値だけで比べると平常時のノイズ（ほぼ全点が震度0 の帯にいる）が閾値を通り、帯が鳴りっぱなしになる。半径内の確定メンバーが**すべて欠測**しているときは全国基準へ倒す（震度0 は「観測できて揺れていない」なので倒さない）
- **地震情報** … 観測点の点と**区域の点の両方**を見る。震度速報は区域別震度しか持たず、多くの地震で最初に届くのがこれ

### なぜ検知エンジンを通すか

音・自動タブ切替・地図の検知点はすべて検知エンジンの結果で動いており、この機能だけが生の観測値を走査していた。機器の異常など地震ではない跳ね上がりは近傍の点が揃わないため、エンジンを通せばメンバーに入らない。

**エンジンの異常も併せて受け取る。** エンジンは連続して壊れると検知結果を空にする（`stalled`）。これを見ないと「揺れが収まった」と区別できず、揺れの最中に帯を引っ込めてしまう。詰まっている間は判定を保留し、揺れの識別子も捨てない。**強震モニタの帯を出している間は地震情報へも落とさない** —— 揺れが続いているのに「強い揺れがありました」（過去形）へ差し替わる。ただし何も出ていない状態まで止めると、エンジンが壊れ続けている端末で地震情報の経路まで死ぬので、そこは通す。

### 表示する震度は発表震度と一致しない

強震モニタのリアルタイム震度は 1〜2 秒の窓で出す速報値で、揺れの継続時間まで見る計測震度より高く振れる。実データ 793 窓の再生では、既定の閾値で帯が出る 22 窓のうち 16 窓が気象庁の発表より高い震度になった（発表が震度1 の地震の震源から 8km で震度5弱相当、発表6強 の地震で震度7相当）。跳ね上がっていたのは震源直上の観測点で、ノイズではなく本物の観測値のため、検知エンジンを通しても変わらない。

数字を発表震度として読ませないのは表示側の役目（§5「強震モニタ経路だけ指標名を出す」）。

## 3. 登録地点の周り

設定に地点（ホーム地点）が登録されていれば、**半径 30km**（`NEARBY_RADIUS_KM`）の中だけで判定する。登録が無ければ全国基準。

### なぜ半径で切るか

「最寄りの 1 点」で代表させると、その点が止まった瞬間に判定が死ぬ。「近い順に K 点」で拾うと、観測点が疎な離島では数百 km 先の本土の点まで数に入り、まったく別の場所の揺れを自分の揺れとして扱う。半径なら、密な地域では多くの点が入って欠測に強く、疎な地域では素直に「近くに点が無い」と分かる。

### 3 つの照合対象

半径内から集めるものが経路ごとに違う。

| 集めるもの | 使う経路 | 照合の相手 |
|---|---|---|
| 強震モニタの観測点キー | 強震モニタ | 検知エンジンが確定したメンバー観測点 |
| 気象庁の観測点名 | 地震情報 | 電文の観測点の点 |
| 一次細分区域名 | EEW・地震情報 | 予想震度の区域・区域の点 |

観測点キーは検知エンジンと同じ生成規則で作る。**同一座標に複数の実体がある観測点が実在する**ため（全 1725 点中 207 グループ・431 点）、座標だけで持つと 2 つ目以降が引けない。

**観測点名に県名を含めない。** 座標テーブルのキーは「県名｜観測点名」だが、DMDATA の電文は観測点も区域も県名を空で積む（[`quake-spec.md`](quake-spec.md) §4）。県名込みで突き合わせると DMDSS 版では構造的に 1 件も一致せず、地点を登録した人ほど判定が死ぬ。

### 「近くに観測点が無い」と「近くの観測点が揺れていない」は別物

前者は判定できないので全国基準へ倒す。後者を同じ扱いにすると、**遠方の地震で毎回出ることになり地点を登録した意味が消える**（電文には震度1以上を観測した観測点しか載らないので、自宅の周りが無感なら 0 件になるのが普通。実測: 2018 年大阪府北部地震を東京の地点で受けると、最初に届く震度速報 3 本がいずれも 0 件になり、全国基準の震度6弱で発火していた）。

全国基準へ倒すのは次の場合。

- 半径内に観測点が 1 つも無い（離島など）
- 半径内の確定メンバーがすべて欠測している（強震モニタ経路）
- **電文の点をこちらの索引で 1 件も引けない**（区域の呼び方が変わった・索引が古い等。判定の材料そのものが無い）

出さないのは次の場合。

- 半径内の点が電文に載っていて閾値未満
- **電文の点を 1 件でも引けるのに、自宅の周りが載っていない**（索引は生きているので「載るほど揺れていない」と読める）
- 半径内に確定メンバーが無い（強震モニタ経路）

### 「載っていない」から何が言えるかは電文の粒度で決まる

観測点の点を持つ電文は、その時点で震度1以上と分かっている観測点を載せる。載っていなければ、その時点では震度1未満と読み、閾値がいくつでも出さない。**観測点は続報で後から加わることがある**が、続報が届けばその地震を判定し直す（§2「同時に成立したら緊急度の順」）。

区域しか持たない電文（震度速報）は震度3以上の区域だけを載せるので、言えるのは「震度3未満」まで。**閾値がそれより低いときは判定できないので全国基準へ倒す。** ここで判定を保留すると、観測点を載せた続報が届かずに終わる地震では、一度も出ないまま終わる。

## 4. 閉じたときの挙動

### 畳む（消さない）

閉じると小さなボタンへ畳む。押せば開く。

大きな地震のあとは余震が続き、続報も次々届く。地震ごとに別物として出し直すと、閉じても閉じても現れる。かといって完全に消すと読み返せない。

### 畳んだままにする 3 条件

畳んでいる間に届いた揺れは、次の**すべて**を満たすときだけボタンのままにする（中身は最新の揺れへ更新し、ボタンの寿命を延ばす）。

1. いま畳んでいること
2. 畳んでから `SUPPRESS_MS`（1 時間）が経っていないこと
3. **震度が畳んだときを超えていないこと**

3 を外すと、震度5弱で閉じたあとの震度6強が伝わらない。逆に、畳んでいる間の揺れで**基準の震度を上書きしない** —— 余震で下がっていく値に追随させると、そのうち小さな揺れでも「上がった」と見なして開いてしまう。

### 寿命

最後に揺れが届いてから `SUPPRESS_MS` を過ぎるとボタンも消える。次の地震は改めて帯として出る。**開いている間は消さない**（読んでいる最中に消えることになるため）。例外は、帯の元になった EEW・地震情報が取り消されたとき（下の「元の EEW・地震情報が取り消されたとき」）。

寿命を延ばすのは残りが半分を切ったときだけ。強震モニタは 1 秒ごとに判定するため、揺れが届くたびに書き換えると保存とタイマーの張り直しが毎秒走る。**延長の判定は表示の更新より先に行う** —— 「中身が変わらないなら触らない」で先に抜けると、同じ震度が続く揺れで延長が一度も走らない。

**消したものは出し直さない。** 消したときの対象を覚えておき、同じものが再び届いても出さない。判定中の地震は 1 時間居座るため、覚えていないと消した次の再描画でそのまま出し直してしまう。この記録は永続化しない —— リロードは「もう一度見たい」ことも意味しうる。

### 元の EEW・地震情報が取り消されたとき

帯の元になった EEW が誤報取消されたら、**開いていても畳んでいても帯を下ろす**。誤報で行動を促し続ける害は、余計に出す害より大きい。

**地震情報も同じ扱いにする**（2026-10-20 ユーザー承認。原文「推しで」、承認した案は「出ている帯の元の地震が取り消されたら、帯を下ろす。緊急地震速報と同じ形にそろえる」）。取り消された地震のカードは取消の表示を 10 秒出してから一覧を外れる（[`quake-spec.md`](quake-spec.md) §6.2）。その間に下ろす。ただし同じ地震の生きたカードが並んでいるとき（取消のあとに出し直された報）は、取り消された扱いにしない。

ただし消して終わりにはしない。判定をやり直し、成立する経路（別の EEW・強震モニタ・地震情報の順。§2）があればその帯へ切り替える。誤報のあとに本当の揺れが来ていることはありうる。どれも成立しなければ消す（寿命が尽きて消した地震しか無い場合も消す）。

**畳んだ記録は、取り消された EEW・地震情報の帯を閉じてできたものなら捨てる。** 記録の震度が取り消された予想や観測（たとえば震度7）から来ているため、残すと本物の揺れが「畳んだときの震度を超えていない」として畳んだままになる。閉じたあと帯が別の EEW へ移っていても、記録の震度は閉じたときのままなので同じく捨てる。

**別の揺れを閉じてできた記録は残す。** 例: 震度6弱の地震の帯を閉じたあと、震度5弱予想の EEW が届いて畳んだまま出ていた。この EEW が取り消されても、利用者が閉じたのは地震の帯なので、畳んだ状態を保つ。

見分けには記録に残した「閉じたときの帯の識別子」を使う。識別子を持たない旧形式の記録は見分けが付かないため、取消のときは捨てる側へ倒す。

### 永続化

畳んだ記録（期限・震度・閉じたときの帯の識別子）は `localStorage`（`action-checklist-suppress`）に残し、**リロード後も畳んだ状態から始める**。記録を保存するだけでは足りない —— 画面の状態を「開いている」から始めると、閉じたあとにリロードした端末で次の余震が帯として開き直る。

記録の震度は**階級表にある値だけを採る**。階級外の値（例: 99）が入ると「これを超えたら開き直す」が永久に成立せず、以後どんな揺れでもボタンが自動で開かなくなる。記録は永続化されるため、一度混入するとリロードでも直らない。

読み書きに失敗しても機能そのものは止めない（畳む動作は続く）。ただし黙って諦めず記録に残す。「閉じてもリロードで開き直す」の原因が読み取り側か書き込み側か切り分けられなくなるため。

## 5. 表示

地図の左上の更新バッジの下、画面上端寄りの中央に置く。下端は特別情報バナーが使っており、あちらは末尾要素で余白を作るため子を足せない（[`architecture-spec.md`](architecture-spec.md) §4）。

**置き場所は `App` が持つ。** 地図に重ねる縦並びの上端に入り、下端の凡例・特別情報バナーと地図の高さを分け合う。地図が低いと帯の中でスクロールし、見出し 1 行ぶんより縮まない（仕組みと理由は [`architecture-spec.md`](architecture-spec.md) §4「地図の上に重ねる帯は、地図の高さを 1 本の縦並びで分け合う」）。このコンポーネント自身は絶対配置しない。

- **畳んだ状態では中身の幅に合わせる。** 固定幅にすると 3 行しかない帯が横に間延びして地図を無駄に覆う
- 帯を畳んだ状態で見せるのは先頭 3 項目（`COLLAPSED_ACTION_COUNT`）。揺れた直後に読めるのはそのくらい
- **震度の表示は常に最大幅（「震度5弱」の 4 文字ぶん）を確保する。** 震度ラベルは階級で 1〜2 文字に揺れるため、成り行きの幅にすると階級が上がるたびに帯とボタンの幅が動く。強震モニタ経路では毎秒変わりうる
- **見出しの下に、判定した経路と範囲を 1 行だけ添える**（2026-10-25 ユーザー選択「この文面で直す (Recommended)」）。判定の仕組みの説明は設定タブの「出す最低震度」に置き、帯には書かない

### 見出しの下の 1 行

範囲は「地点を登録しているか」ではなく、**判定が実際に使った範囲**（`ChecklistScope`。`judge*ForScope` が判定と同時に返す）で選ぶ。地点があっても、近くの観測点を電文に引けない・半径内がそろって欠測・自宅の区域を引けない、のどれかで全国基準へ倒れる。そのとき「ホーム地点から 30km 以内」と名乗ると嘘になる。

| 経路 | ホーム地点の周りで判定 | 全国基準へ倒れた・地点なし |
|---|---|---|
| EEW（区域の予想） | 緊急地震速報・ホーム地点の地域の予想 | 緊急地震速報・全国の最大 |
| EEW（「非常に強い揺れを検知」の報） | 緊急地震速報・ホーム地点から 30km 以内で検知 | （同じ） |
| 強震モニタ | 強震モニタ・ホーム地点から 30km 以内 | 強震モニタ・全国の最大 |
| 地震情報 | 地震情報・ホーム地点から 30km 以内の観測点 | 地震情報・全国の最大 |
| 地震情報（最大値が区域の点。震度速報など） | 地震情報・ホーム地点の地域 | （同じ） |

30km は `NEARBY_RADIUS_KM` から組む（§3）。

地震情報の区域の点は 30km の円ではなく区域名の一致で引く（§3）ので、最大値が区域の点から来たときは「30km 以内の観測点」と名乗らない（`nearArea`。2026-10-25 ユーザー選択「観測点と区域で分ける (Recommended)」）。同じ震度の観測点もあれば、観測点の方を名乗る。

### 強震モニタ経路だけ指標名を出す

この経路が見ているのは気象庁の発表震度とは別の指標で、同じ地震でも高く振れる（§2「表示する震度は発表震度と一致しない」）。「震度7」とだけ書くと、同じ画面の地震カードに出ている発表震度と食い違って見えるため、この経路では「リアルタイム」を添える。

**名前は横に伸ばさず上へ小さく乗せる。** 「リアルタイム震度5弱」を 1 行で書くと、帯と畳んだボタンが間延びして地図を覆う。緊急地震速報は予想値・地震情報は発表値なので、そちらは「震度○」のまま。

### 見出しは EEW だけ言い分ける

| 経路 | ホーム地点の周りで判定 | 全国基準へ倒れた・地点なし |
|---|---|---|
| EEW | 強い揺れが来ます | 強い揺れが予想されています |
| 強震モニタ | 強い揺れを観測しています | （同じ） |
| 地震情報 | 強い揺れがありました | （同じ） |

「来ます」は読み手のところへ揺れが向かうという意味になるため、全国のどこかで予想が出ているだけの状態で使うと嘘になる。**言い分けも見出しの下の 1 行と同じく、判定が実際に使った範囲で選ぶ** —— 地点があっても自宅の区域を引けずに全国基準で判定したなら「予想されています」にする。「観測しています」「ありました」は場所を主張しない事実の記述なので、地点が無くてもそのまま成り立つ。

## 6. 内容と出典

載せるのは公的機関が挙げているものだけで、独自の判断で項目を足さない。出典は画面にも出し、最後に「気象庁・自治体の指示に従う」と添える。ここは行動を促す場所であって、公的な指示に置き換わるものではない。

- 東京消防庁「地震 その時10のポイント」
- 消防庁「非常用持出品チェックシート」

持ち出すものは避難を決めた後に見るものなので、直後の行動とは別の折りたたみに分けている。

## 7. エッジケース

| 状況 | 挙動 |
|---|---|
| 同じ EEW の続報で予想震度が上がった | 表示を更新する（識別子だけで弾くと引き上げを取りこぼす） |
| 同じ EEW の続報で報番号だけが進んだ | 何もしない（識別子に報番号を含めないため） |
| EEW が誤報取消された | その EEW は判定から外れる。取消かどうかは `cancelledAt` で見る（[`eew-spec.md`](eew-spec.md)「取消かどうかは `cancelledAt` で見る」） |
| 出している帯の元の EEW が誤報取消された | 帯を下ろし、判定をやり直す。別の EEW・強震モニタ・地震情報のどれかが成立すればその帯へ切り替え、どれも成立しなければ消す（§4「元の EEW・地震情報が取り消されたとき」） |
| 出している帯の元の地震情報が取り消された | 同上。同じ地震の生きたカードが並んでいれば下ろさない |
| 取消表示中の地震カード | 判定しない（同じ地震の生きたカードと並んでいても、取消カードの震度は使わない） |
| 取り消された EEW の帯を閉じて畳んでいた | 畳んだ記録を捨てる。別の揺れを閉じてできた記録は残す（§4 同上） |
| 最終報のあとの自動解除で EEW が消えてから、取消の電文が届いた | **既知の制限:** 帯は残る。取消を当てる EEW がもう無く、取消だと分からないため。自動解除の前に届いた取消なら下ろす |
| 強震モニタが揺れ続けている | 識別子は揺れの間ずっと同じ。直近の EEW か地震があればそれに紐づけ、無ければ閾値を超えた時刻を使う（丸めない） |
| 観測点の座標データが未取得 | 全国基準で判定する（地点を登録していても） |
| 検知エンジンが詰まった（`stalled`） | 判定を保留する。出ている帯・揺れの識別子はそのまま保つ。強震モニタの帯を出している間は地震情報へも落とさない |
| 検知エンジンが詰まっているが、何も出ていない | 地震情報の経路は通常どおり働く |
| 半径内に確定メンバーが無い | 出さない（「近所は揺れていない」と読む） |
| 電文の点をこちらの索引で 1 件も引けない | 全国基準で判定する |
| 震度速報しか届いていない状態で、閾値が震度1・2 | 全国基準で判定する（区域からは「震度3未満」までしか言えないため） |
| 自宅の周りの観測点名だけが索引から欠落している | 検出できない。全国のどこか 1 点でも引ければ索引は生きていると判断するため（`station-coords.json` の再生成漏れ・観測点の改称で起こりうる） |
| 壊れた畳み記録が `localStorage` にある | 無かったことにして帯を出す |
| EEW と地震情報が同時に閾値を超えている | EEW を見せる（§2「同時に成立したら緊急度の順」） |
| 寿命が尽きて消えたあと、同じ地震が最新のまま残っている | 出し直さない |
| 先頭でない地震に続報が届き、近所の点が加わって閾値に達した | 出す（§2「同時に成立したら緊急度の順」） |
| 起動時の履歴・「もっと見る」で、閾値に達する古い地震が入った | 出さない（先頭でない地震が初めて現れただけでは判定しない） |
| 判定する地震が 2 件とも閾値に達している | 深刻な方を見せる（同じ震度なら地震の時刻が新しい方） |
| 気づいてから 1 時間を過ぎた地震 | より深刻でも選ばない。続報が届けばそこから 1 時間また判定する |
| 寿命が尽きて消した地震より低い地震が閾値に達した | 低い方の帯を出す（消した地震は選ぶ前に外す） |
| 平常時（どの観測点も震度0） | 閾値を震度1 まで下げても出さない |
| 観測網が疎な地点で震度1〜3 の揺れ | 強震モニタ経路では出ないことがある。検知エンジンは弱い揺れの確定に近傍の複数点を要求するため（[`kyoshin-detection-spec.md`](kyoshin-detection-spec.md) §4）。地震情報の経路で拾う |
| 半径内の確定メンバーがすべて欠測 | 全国基準で判定し直す（強震モニタ経路） |
| EEW が 2 件同時に出ている | 深刻な方を見せる |
| 設定で「行動チェックリスト」を切った | 開いている帯も畳んだボタンも引っ込める（畳んだ記録は残す） |
| 寿命が尽きて消えたあと、同じ地震の**遅れた続報**が届いた | **再表示しない**（消した対象を覚えているため）。確定情報は通常 1 時間以内に出揃うので実害は小さいが、この設計上そうなる |
| EEW も地震情報も無い窓で、別々の地震が続けて起きた | 揺れが一度収まっていれば別のものとして扱う（識別子に閾値を超えた時刻を使い、丸めない） |
