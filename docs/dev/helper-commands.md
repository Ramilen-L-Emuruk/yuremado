# 補助コマンド

> [`CLAUDE.md`](../../CLAUDE.md) の同名の節から案内される詳細。いつ開くかは `CLAUDE.md` 側に書いてある。

| コマンド | 用途 |
|----------|------|
| `npm run dev` | 開発サーバー |
| `npm run dev:list` | いま動いている dev サーバーの一覧（ポート・場所・バリアント・PID・起動時刻・起動したセッション）。**台帳（`.dev-server.json`）に無いのに動いているもの＝孤児も併せて出す** —— 門を通らない起動（`npx vite` を直に叩く等）や、門を入れる前から動いているものは台帳に載らないため。**台帳だけを見て「他には無い」と判断しない**。孤児の検出は `netstat` と PowerShell に頼るので Windows のみ。**他の OS では、また呼び出しに失敗したときも「0 本」ではなく「調べていない」と分かる文言を出す**（両者を見分けられなくしないため）。**起動コマンドにこのリポジトリのパスが無いものは「このプロジェクト外」として分ける** —— 同じ端末では別プロジェクトの vite も動いており、断定的なラベルを付けると他人の作業を止めさせることになる |
| `npm run build` | 地名ラベル用グリフの検証 + 型チェック + 本番ビルド + **precache 予算の検査**（1 ファイルが上限の 85% を超えたら exit 1。→ [`docs/spec/settings-pwa-spec.md`](../../docs/spec/settings-pwa-spec.md) §5「上限の手前で止める」） |
| `npm run preview` | 本番ビルドのプレビュー（サブパス配信） |
| `npm test` | ユニットテスト（Vitest）を 1 回実行（CI との関係は[`CLAUDE.md`](../../CLAUDE.md)「検証」節） |
| `node scripts/build-station-coords.mjs` | 観測点座標テーブル（`public/data/station-coords.json`）の再生成。**実行後は `npm test` を通すこと**（このファイルのキー順が読み上げの地域順の情報源のため、上流データの並びが変わると読み上げ順だけが静かに崩れる。`stationCoords.test.ts` がその前提を検証する）。**現行の観測点だけでなく、取得元のリビジョン履歴を遡って「現行の一覧に無い観測点」も集める**（`unlisted`）—— 観測点の統廃合は毎年続き、過去の電文を再生すると当時あって今は無い観測点が座標を引けず地図から消えるため。**区域の代表点（`areas`）には混ぜない**（代表点は観測点座標の平均なので、混ぜると震度速報の描画・カメラの寄り先・読み上げの距離選抜がまとめてずれる）。**中身を読めたリビジョンの数**（歯止めの本体。件数は「履歴を辿れたか」の代理値でしかない）・**固定しているリビジョンが上流の一覧に含まれること**・件数の幅・現行との重複・既知の 2 点の有無・新しい区域名を持ち込まないことを検査し、合わなければ exit 1 で止まる。**取得元と履歴の走査は読み仮名側（`build-station-readings`）と共有する**（`scripts/lib/stationSource.mjs`）—— 別々に持つと座標と読みが違う版から作られる。詳細は [`docs/spec/data-sources-spec.md`](../../docs/spec/data-sources-spec.md) §6「現行の一覧に無い観測点」 |
| `npm run build-station-readings` | 観測点名の読み（`public/data/tts-station-readings.json`）の再生成。**要 VOICEVOX**（既定 `http://localhost:50021`・`--engine` / `--speaker` で変更可）**＋要 Python の形態素解析**（`pip install fugashi unidic-lite`。読みの長音を開くのに使う。`PYTHON` 環境変数で実行するコマンドを変えられる。**開けなければ生成を止める** —— 長音でない音で鳴る辞書が「直したつもり」で書き出されると、生成物を見ても気づけない）。「どの観測点をエンジンが誤読するか」を実際に読ませて判定し、**誤読する点だけ**を収録する（全点を入れると正しく読める点までアクセントと句切れが崩れる）。**対象は 2 つ**＝震度観測点（「5弱以上・未入電」の地点名）と潮位観測点（津波の観測情報）。前者は震度観測点一覧、後者は気象庁の個別コード表（PointTsunami）から取る。**長い名前は市町村の境界で 2 アクセント句に割る**（割れ目と読みは同じコード表の AreaInformationCity から取り、前半の核はエンジンへ訊く）。**震度観測点は現行の一覧だけでなく「現行の一覧に無い観測点」も含める**（座標側と同じ `scripts/lib/stationSource.mjs` で集める）—— 過去の電文を再生すると当時の観測点名が声になり、上流が更新されれば後から加わった観測点がライブでも声になるため。**観測点が新設されたら実行する**。判定結果は生成物に焼き込まれるので**他の環境で作り直す必要はない**。上流の件数・既知の点のふりがな・距離部分の読み・作った読みの往復検証のいずれかが合わなければ exit 1 で止まる。ほかにも読めないふりがな・誤読の判定が 0 件や大半といった形でも失敗する（一覧は仕様書）。**句割りは「判定に掛けた点のうち割れた割合が 8 割を下回ったら」止める** —— これが無いと、判定が壊れて全件が見送りへ倒れても従来どおりの辞書が書き出され、句数の検証も一度も発火しないまま正常終了する。詳細は [`docs/spec/audio-tts-spec.md`](../../docs/spec/audio-tts-spec.md) §3「震度観測点名の読み」「潮位観測点名の読み」「観測点名の句割り」 |
| `npm run build-epicenter-accents` | 震央地名の句割り（`public/data/tts-epicenter-accents.json`）の再生成。**要 VOICEVOX ＋ Python の形態素解析**（`build-station-readings` と同じ。理由もそちら）。エンジンが 1 アクセント句にまとめてしまう長い震央地名（8 モーラ以上）を、前部要素と後部要素の境界で割る指定を作る。**各句の核はエンジンへ訊く**（構成要素を単独で読ませて 1 句・読みが一致したときだけ採り、採れなければ末尾核へ倒す。「〜地方」だけは実測より優先して「チ」へ置く）。**実測できた割合が半分を下回ったら止める**（`MIN_MEASURED_RATIO`）＝採れなければ末尾核へ倒れるので句数も読みも検証を通り、核の位置だけが黙って戻る。採れなかった語は名前を出す。**後部要素が 3 モーラ未満なら割らない**（`MIN_TAIL_MORAS = 3`。落ちるのは `能登半島沖` だけで、助詞を取り込むと短い句が浮くため）。**「〜地方」で終わる名前は句割りの門（8 モーラ以上の 1 句）を通さず、核だけを「チ」へ置く**（県名が前に付けば「県」で割る。エンジンは「ホ」の後へ置くので短い名前が崩れたまま残っていた）。**誤読はこの辞書の担当ではない**（手書きの句区切り辞書が全件手当て済み）。上流の件数・既知の点のふりがな・作った句割りの検証・**長音を開いた値の検証**のいずれかが合わなければ exit 1 で止まる。詳細は [`docs/spec/audio-tts-spec.md`](../../docs/spec/audio-tts-spec.md) §3「震央地名の句割り」 |
| `npm run build-travel-time-table` | JMA2001 走時表（`src/data/jma2001TravelTime.ts`）の再生成。**API キー不要**。気象庁の配布 zip を落として `.cache/jma2001-cache/` に残し、検査を通してから書き出す。**上流のファイルは 2005-04-14 付けで固定なので定期実行は要らない** —— 走らせるのは表の持ち方（丸めの単位・符号化）を変えたときだけ。zip の中身・格子の刻み幅・既知 9 組の実値・距離方向の非減少（0.01 秒へ丸めるので平坦部があり、厳密な増加ではない）・P が S より速いこと・Uint16 に収まること・**書き出した base64 を復号し直して全 50,032 個が一致すること**を検査し、合わなければ exit 1 で止まる。詳細は [`docs/spec/data-sources-spec.md`](../../docs/spec/data-sources-spec.md) §6「JMA2001 走時表」 |
| `npm run build-public-stations` | 公開観測点の表（`public/data/public-stations.json`）の再生成。**API キー不要**。気象庁の広帯域地震計（EarthScope の `JP` 網）の観測点情報を FDSN の station サービスから 2 本取り、`.cache/public-stations-cache/` に残す（2 回目以降は読むだけ。取り直しは `-- --refresh`、投げる先だけ見るなら `-- --dry-run`）。**観測点は移設・コードの付け替えで運用期間（エポック）が分かれるので、エポックごとに 1 行を持つ**。日本語の名前（気象庁の観測点一覧の観測点名）は上流に無いのでスクリプトの中に手で持ち、**名前の無い観測点が現れたら止まる**。ほかに 3 成分（BHE・BHN・BHZ）が 1 件ずつ揃わない・向き（方位・傾斜）が成分の名前と合わない・感度が 1.0×10⁹ の ±1% を外れる・採取率が 20 Hz でない（実データで 20 Hz と確かめた `YOJ.BHN` の 30.113 Hz だけ通す）・既知の 3 観測点（JMN・ASAJ・YOJ）の座標と期間が動いた・同じコードのエポックが重なる、のどれでも exit 1 で止まり、成分の座標・終わり・単位のずれや名前の表の取り残しのような上流の形の変化でも止まる。**波形の成分を持たないエポックは、確かめた 2 つ（JMJ・JMJ2）だけを外して生成物の `excluded` に残す** —— それ以外が成分を持たなければ止まる（応答の欠けで観測点が黙って消えないように）。終わりの時刻は秒へ切り上げた半開区間で持つ（次のエポックの始めと揃う）。観測点が新設・移設されたら実行する。設計は [`docs/public-waveform-design.md`](../../docs/public-waveform-design.md) §3.1 |
| `npm run sign-arrival-token` | 到達予想トークンの発行。`-- --init` で鍵の組を作り（初回だけ。秘密鍵を `.env.local` へ書き、公開鍵を標準出力へ出す）、`-- --subject=<相手> [--days=N]` でトークンを 1 本発行する（既定 365 日）。**秘密鍵は配らない・リポジトリに入れない。** **`.env.local` はワークツリーへ引き継がれないので、メインリポジトリ直下にも置くこと** —— ワークツリー側にだけ置くと、消した時点で発行済みのトークンが全部無効になる。詳細は [`docs/spec/settings-pwa-spec.md`](../../docs/spec/settings-pwa-spec.md) §4.7「到達予想キー」 |
| `npm run verify-particle-phrases` | 辞書の読みへ助詞を連結しても**アクセント句の数とモーラ列が変わらない**ことを実データで確かめる。**要 VOICEVOX**（既定 `http://localhost:50021`・`--engine` / `--speaker` で変更可）。読み仮名辞書の該当語の直後に来る助詞は、読みへ文字列として足してから 1 つのアクセント句へ入れる。この足し戻しが句の数を変えないことが仕組みの前提で、**句が増えれば助詞が独立した句として浮き、直そうとした症状（1 モーラで自ら核を持つ句）が黙って戻る**。**辞書を作り直したとき**（`build-station-readings` / `build-epicenter-accents` / 手書き辞書の編集）と**助詞を足したとき**に実行する。**CI では代われない** —— 判定に音声合成エンジンが要る。3 辞書の全エントリ × 全助詞を突き合わせ、句数・モーラ列のいずれかが合わなければ exit 1 で止まる。詳細は [`docs/spec/audio-tts-spec.md`](../../docs/spec/audio-tts-spec.md) §3「助詞は辞書の読みへ取り込む」 |
| `npm run audit-accent-unidic` | 読み上げに出る名前の**アクセント核**を、エンジンとは別の出典（[UniDic](https://clrd.ninjal.ac.jp/unidic/) 現代書き言葉フルパッケージの `lex_3_1.csv`・28 列目のアクセント型）と突き合わせる監査。**要 VOICEVOX**（既定 `http://localhost:50021`・`--engine` / `--speaker` で変更可）。エンジンが置く核は、語が内蔵辞書にあればその値・無ければ推定なので、**推定が外れた語は読みも句数も正しく、誤読の突き合わせにも句割りの判定にも掛からない**。**zip 全体 1.75GB のうち圧縮 25MB だけを HTTP Range で抜く**（目録を読んで該当エントリだけ取り、`.cache/unidic-cache/` に残す）。既定の対象は 3 辞書のキーと `public/data` の地名と警報対象地方で 3241 語、`--upstream` を付けると震央地名・震度観測点・**詳細震央地名**の上流も取って 6233 語（海外の地名は読点でも割って入れる。読み上げがそこでチャンクを割るため）。**`--components` を付けると「名前を割った構成要素」も対象へ加える**（震央地名の前部・後部要素と、観測点名の市町村。**UniDic に 1 語として載る語が 26 → 116 語へ増える** —— 複合語まるごとは載らないが構成要素は載ることがあるため。気象庁の個別コード表を取るので通信が増える）。**`--bare-check` を付けると「1 語としてエンジンの辞書にあるか」も調べる**（観測点名まで見るには `--upstream` と併用する）＝辞書に値が無い語を読点あり／なしで読み比べ、読みが変わるものを出す（`甲信` を見つけたのはこれ）。エンジンへの問い合わせが倍になるので既定では回さない。**比べられるのは名前まるごとが 1 語として載っているものだけ**（183 語。カタカナの外国地名はよく載るので、詳細震央地名を入れて 29 語から増えた）で、**句ごとには比べない** ——複合語のアクセントは構成要素の単語アクセントと別物で偽陽性だらけになる。**食い違いが出ても exit 0** ＝ 正解を決めるのは耳で、これは候補を出すところまで。取得そのものに失敗したときだけ exit 1（列位置は既知の語で検算する）。**辞書を作り直したとき・観測点や区域が増えたとき**に実行する。詳細は [`docs/spec/audio-tts-spec.md`](../../docs/spec/audio-tts-spec.md) §3「エンジンが置く核が外れているとき」 |
| `npm run build-third-party-licenses` | 同梱する第三者ソフトウェアのライセンス全文（`public/third-party-licenses.txt`）の再生成。**API キー不要・通信なし**（`node_modules` から集める）。**対象は直接の依存だけでなく、そこから辿れる推移的な依存も含む**（実測 32 件。`react-dom` が引く `scheduler`、`maplibre-gl` が引く `@mapbox/*` も配布物へ入る。**うち `@types/geojson` は型定義だけで実行時コードを持たない**が、`maplibre-gl` が `dependencies` に宣言しているので閉包へ入る —— 載せすぎは害にならないので除外していない）。あわせて **`vite-plugin-pwa` が Service Worker へ注入する Workbox** も載せる（devDependencies なので依存グラフでは辿れない。ビルド成果物を見て確かめたものだけを足すこと）。**依存を足し引きしたら実行する** —— MIT も BSD-3-Clause も著作権表示とライセンス文を配布物に含めることを条件としているのに、足りなくても型チェックもビルドも通り画面にも出ない。上流が LICENSE ファイルを配っていない依存だけは代替の文面をスクリプト側に持つ（現在は `murmurhash-js` の 1 件）。**全件が載っていることは [`scripts/thirdPartyLicenses.test.ts`](../../scripts/thirdPartyLicenses.test.ts) が `npm test` で検査する** |
| `npm run check-personal-info -- <--range 範囲 \| --all \| --text ファイル…>` | 公開する内容に個人情報が無いかを確かめる。**push の前には pre-push フックが自動で走らせる**ので、手で回すのは git の外の文章（PR の本文など）を出す前と、履歴全体を見直すとき（`--all`。数分かかる）。**メインの checkout に照合ファイル（`.claude/personal-info.txt`）が無いと止まる**（終了コード 2）。依存を足して作者の連絡先が載ったら許可リストへ理由つきで足す。詳細は[`CLAUDE.md`](../../CLAUDE.md)「公開する前に個人情報が無いことを確かめる」 |
| `npm run check-commit-messages -- --range <範囲>` | コミットメッセージに英語の文が無いかを確かめる（[`CLAUDE.md`](../../CLAUDE.md)「リポジトリに書く文も日本語で書く（機械で止める）」）。`--range` の後ろは `git log` に渡す範囲。終了コードは 0＝無し・1＝見つかった・2＝調べられない。**push の前には pre-push フックが自動で走らせる**ので、手で回すのはフックの届かない経路で出す前だけ。例: `--range origin/main..HEAD` |
| `npm run install-git-hooks` | `check-personal-info` と `check-commit-messages` の 2 つの検査を push の前に走らせるフックを入れる。**clone した端末ごとに 1 回**（フックは git の管理外なので clone では入らない）。中継だけを置き、本体（`scripts/git-hooks/pre-push`）が見つからなければ push を止める |
| `npm run list-ui-strings -- [--out <TSV>] <パス…>` | 日本語を含む文字列を、`.ts`・`.tsx`・`.html` の構文から一覧にする（コメントは拾わない・HTML はタグを外して地の文と、日本語を含む属性の値だけ）。文言を見直す前の棚卸しに使う。拾えない形（英語だけの文言・JSON）と使い方は [`docs/ui-wording-procedure.md`](../../docs/ui-wording-procedure.md)「1. 棚卸しは機械で取る」 |
| `npm run find-locale-strings -- <言語ファイル> <語…>` | ほかのアプリ（Chrome の `ja.pak`・VS Code の日本語パック）の画面の文言を、手元の言語ファイルから探す。言語ファイルの場所は同じ手順書の「3. 語の出どころを探す」 |
