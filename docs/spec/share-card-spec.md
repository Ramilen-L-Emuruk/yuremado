# 共有カード仕様書

> 本書は**現在の実装が表示中の地図をどう 1 枚の画像にするか**をまとめた仕様書。実コードと食い違う場合は実コードを正とする。
> 関連: [`map-rendering-spec.md`](map-rendering-spec.md) の地図の投影とカメラ、[`tsunami-spec.md`](tsunami-spec.md) の観測点、[`eew-spec.md`](eew-spec.md) の区分の呼び方。

## 1. 概要

表示中の地図に見出しと出典を添えて 1 枚の画像にし、共有または保存する。

| 対応ファイル | 役割 |
|---|---|
| `src/components/Map/gl/captureMap.ts` | 地図を指定寸法で撮る |
| `src/utils/shareCard.ts` | 見出し帯・地図・出典帯を合成し、共有または保存へ渡す |
| `src/utils/shareCardContent.ts` | 見出しと出典・注意文を組み立てる |
| `src/hooks/useShareCard.ts` | 撮影から共有までの流れと状態 |
| `src/components/ShareCardButton.tsx` | 地図に重ねるボタン |

## 2. 起動点

地図の左下に重ねたボタン 1 つ（右下は凡例）。特別情報の帯が出ているときは、そのすぐ上に置く（置き方は [`architecture-spec.md`](architecture-spec.md) §4「地図の上に重ねる帯は、地図の高さを 1 本の縦並びで分け合う」）。

**撮るときは、地図の追従が最後に寄せた目標（震度の点・予報円・津波の海岸線など）へ、カードの寸法で寄せ直す**（理由と細部は §5「追従の目標へ寄せ直す」）。

## 3. カードの構成

上から見出し帯・地図・出典帯の 3 段。**全体の寸法は設定の窓の「共有カードの寸法」で選び**（下記「寸法の決め方」）、地図はその残りに割り当てる。

見出しの中身は地図のモードで変わる。

| モード | 見出し | 副見出し | 右上の時刻 |
|---|---|---|---|
| 地震 | 最大震度（震度の色つき） | 震源名・規模・深さ | `地震発現時刻 2026/06/06 08:47:00` |
| 津波 | 最も重い等級（予報だけなら「津波予報（若干の海面変動）」） | 震源名・対象の区域数 | 発表時刻 |
| リアルタイム震度（発報なし・揺れ検知なし） | リアルタイム震度 | — | — |
| リアルタイム震度（発報なし・揺れ検知中） | 揺れ検知／揺れの可能性 | 推定最大震度（強震モニタ） | — |
| リアルタイム震度（発報中） | 緊急地震速報／地震動予報 | 震源名・規模・深さ・予想最大震度・予想長周期地震動階級（発表中の全件） | `第3報　地震発生時刻 2026/10/30 12:00:00　地震発現時刻 2026/10/30 12:00:20` |

**緊急地震速報の右上には、報番号・地震発生時刻・地震発現時刻を並べる**（2026-10-30 ユーザー選択「共有カードだけ (Recommended)」「2 つとも名前を付ける (Recommended)」）。どちらも気象庁の名前を前に付け、秒まで焼く（`kyoshinContent`）。発現時刻を配信しない報（標準版の Yahoo hypoInfo）と発生時刻を持たない報（「非常に強い揺れを検知」）では、無い方の欄だけを落とす。

**緊急地震速報の副見出しには、カードと同じ語で予想を焼く**（2026-10-30 ユーザー選択「0 も階級も焼く (Recommended)」。`eewSubtitle`）。最大予想震度 0 の報は「予想最大震度 0」、予想長周期地震動階級はカードに出す報でだけ「予想長周期地震動 階級2」「階級4程度以上」の形で焼き、電文が階級 0 と言い切った報では「予想長周期地震動 階級0」と焼く（出す条件はカードと同じ `canPresentLpgmClass`・`statesEewLpgmClassZero`。→ [`eew-spec.md`](eew-spec.md) §4）。

**規模と深さは、判らなくても「M不明」「深さ 不明」と焼く**（2026-10-23 ユーザー選択「「不明」も焼く」。推した「今のまま」ではない。語は 2026-10-24 ユーザー選択「この語で (Recommended)」）。以前は項目ごと落としていたが、落とすと「規模を伝えていない」のか「規模が判らない」のかが画像から読めない。「M」を付けるのは、何が不明なのか読めるようにするため（`shareMagnitudeText`・`shareDepthText`）。地震・津波の原因地震・緊急地震速報で同じ語にする。

**ただし、震源そのものを伝えていない地震情報（震度速報。震源の座標がセンチネル）では、規模も深さも足さない。** その電文は規模・深さを「不明」と言っているのではなく、まだ伝えていない（判定は `hasKnownEpicenter`）。

震度が階級表に無い値で届いた場合（震度を伝えない電文）は、見出しを「地震情報」に落とす。

**副見出しが帯の幅に収まらなければ折り返す**（最大 3 行。超えた分は 3 行目の末尾を「…」で切る。`layoutSubtitleLines`）。**切るのは項目の境目まで**で、1 文字ずつ削らない —— 「M7.6」が「M7…」になると数値の欠けが省略の印と見分けられない。切ったことは記録に残す（共有シートへ渡す本文には全文が載る）。複数の緊急地震速報や津波の原因地震を全件並べると 1 行に収まらないため（2026-10-23 ユーザー選択「全件を並べる」・並べ方は 2026-10-24 ユーザー選択「副見出しで折り返す (Recommended)」）。折るのは区切り（全角の空き・「／」）のところで、1 つの項目（「石川県能登地方　M7.6」）が行をまたがないようにする。区切りの無い長い項目だけは文字の途中で折る。

- **見出し帯の高さは行数で伸び、そのぶん地図が縮む。** 地図の高さは撮影の前に決める必要があるので、行数は撮影の前に数える（`shareCardSubtitleLines`）。数える関数と描く関数は同じ `layoutSubtitleLines` を通す —— 別々に持つと、撮った地図の高さと合成のときの高さがずれて、地図が引き伸ばされる（`shareCardMapHeight` に行数を渡す）
- 文字幅を測れない環境（2D の文脈が取れない）では 1 行として扱う

**リアルタイム震度で緊急地震速報が複数発表中なら、副見出しに全件を「 ／ 」で並べる**（2026-10-23 ユーザー選択「全件を並べる」）。並びは深刻な順（区分 → 予想最大震度。同じなら受け取った順。`sortEewsBySeverity`）で、見出しの区分・色と右上の報番号・地震発生時刻・地震発現時刻は最も深刻な 1 件のまま。緊急地震速報の深さも焼く（2026-10-23 ユーザー選択「どちらも出す (Recommended)」）。

**緊急地震速報が無くても、強震モニタで揺れを検知していれば、検知と推定最大震度を出す**（2026-10-23 ユーザー選択「揺れ検知中は推定最大震度を出す (Recommended)」。文面は 2026-10-24 ユーザー選択「この文面で (Recommended)」。`detectionContent`）。見出しはウィンドウタイトルと同じ「揺れ検知」／「揺れの可能性」、副見出しはブラウザ通知の本文と同じ「推定最大震度 5弱（強震モニタ）」の形。推定最大震度の呼び名は通知と同じ（`kyoshinDetectionScaleLabel`）で、震度0 未満は「推定最大震度 0以下（強震モニタ）」と焼く（2026-10-29 ユーザー選択「「0以下」を焼く (Recommended)」。測った値で、不明ではない）。欠測なら副見出しは出さない（通知は「?」を出すが、画像は訂正できないので焼かない）。材料は `App.tsx` が渡す `kyoshinDetection`（推定最大震度は通知と同じ `effectiveKyoshinMaxIndex`）。

**緊急地震速報の震央地名が空のときだけは、震源名の位置に「震源調査中」を置く**（画面のカード・地図の吹き出しと同じ語。2026-10-22 ユーザー承認「「震源調査中」を入れる」。→ [`eew-spec.md`](eew-spec.md) §5「震央地名が空なだけの報は、仮の震源として扱わない」）。

**津波の見出しは、予報だけのときも等級を名乗る**（予報だけでも等級を見出しにすると決めた。2026-10-21 ユーザー選択「おすすめで」）。警報・注意報が無く、区域がすべて予報なら「津波予報（若干の海面変動）」とし、副見出しと時刻は他の等級と同じに出す。等級の読めない区域が 1 つでも混じれば予報と言い切らず、区域が 1 つも無いときと同じく「津波情報」に落とす（ウィンドウタイトルの名乗りと同じ判定 `isTsunamiForecastOnly`。→ [`audio-tts-spec.md`](audio-tts-spec.md) §5「タイトル表」）。解除表示中の津波は見出しにも副見出しにも数えない（材料を同じ集合から作る）。

**津波の見出しには文字色を付けず、既定の白で出す**（同日のユーザー選択「おすすめで」）。`formatTsunamiGrade` が返す `color` は等級の色地（`bg`）の上に載せる文字の色で、注意報では黒になり、暗い見出し帯の上では読めない。`bg` を文字色に流用もしない —— 大津波警報の紫はこの帯の上でコントラスト比が 2.5 ほどしか取れない。

**「5弱以上・未入電」は断定形で出さない。** 見出しの最大震度に「以上」を添える
（`getIntensityLabelWithOrAbove`。判定は `points` から導く ―― → [`quake-spec.md`](quake-spec.md)
§4「震度5弱以上未入電」）。画像は後から訂正できないので、画面より強く言わない。

**規模を数値で出せないときは、電文が添えた言い回しを出す**（「M8を超える巨大地震」等）。
気象庁は規模が確定していない段階でこの形を使う。数値が無いことを理由に項目ごと落とすと、
「規模が判っていない」ことすら伝わらない。**地震・津波のどちらの見出しも
`formatMagnitudeWithCondition` / `formatMagnitudeCondition` を通す** —— 素通しにすると、同じ電文
由来の同じ事実が地震の共有カードでは半角・津波の共有カードでは全角、と表記が割れる。
**緊急地震速報の見出しも同じ規則**（2026-10-22 ユーザー承認「吹き出しと共有カードも揃える (Recommended)」）。説明が無く
整形の結果が「不明」だけになるときは、上のとおり「M不明」と焼く（`shareMagnitudeText`）。

**津波の原因地震が複数あるときは全件を「 ／ 」で並べる**（2026-10-15 ユーザー承認「全件を並べる」。2026-10-19 ユーザー選択「全件を並べる（今の形） (推奨)」で維持）。

複数の報が運ぶので、震源名・規模・地震発現時刻の組が同じものは 1 つにまとめる。各地震には深さも添える（判らなければ「深さ 不明」。2026-10-23 ユーザー選択「どちらも出す (Recommended)」）。規模も説明も無ければ「M不明」（時刻を読めない側は別の地震と決められないので、同じ震源名・規模の地震とまとめる）。

## 4. 出典と注意文

画像は本文から切り離されて流通するため、**出典は画像そのものに焼き込む**。出典は 1 行にまとめる——行を増やすとそのぶん地図に割ける高さが減る。

**幅に収まらなければ折り返し、切り詰めない**（`layoutNoticeLines`。読点・句点・「／」のところで折る）。幅 1080 の寸法（正方形・縦長）では緊急地震速報の注意文が 1 行に収まらず、切り詰めると末尾の「震源に近い場所では強い揺れに間に合わないことがあります」が落ちる。PB2002 の帰属表示は利用条件なので出典も落とせない。**地図の高さは折り返した後の行数で決める**（`shareCardNoticeLines`。撮影の前と合成で同じ関数を通す）。16:9 では注意文も 1 行に収まる。

| 挙げるもの | 出す条件 | 求める規約 |
|---|---|---|
| 気象庁 | 常に | 公共データ利用規約（第 1.0 版） |
| GEBCO・NOAA NCEI（Esri のタイルサービス経由） | 海底地形の表示が入りのとき | 配信元のサービスが `copyrightText` で求める帰属表示（GEBCO と NOAA NCEI の両方） |
| 産総研 活断層データベース | 地震／リアルタイム震度／震源カタログモードで、活断層の表示が入りのとき | 政府標準利用規約 2.0 |
| PB2002 (Bird, 2003) | 上の 3 つに津波モードを加えたモードで、プレート境界の表示が入りのとき | Open Data Commons Attribution License |
| EarthScope | 公開観測点の三角の印を描いているとき（下部に公開観測点の波形を出している間はモードを問わず、出していなければ地震モードで公開観測点の波形がある地震カードを開いている間） | CC BY 4.0（網の運用者と配信した施設の両方を挙げる。運用者の気象庁は上の行が既に挙げている） |

**描いているものだけを挙げる**（2026-10-23 選択「今のまま記録する (Recommended)」。08-30 の「ヘッダ＋地図＋出典フッタ（推奨）」が覆っていなかった絞り込みを諮り直した）。挙げないのは帰属表示の欠落になり、描いていないものを挙げても読み手は画像の中に見つけられない。活断層は地震／リアルタイム震度／震源カタログモードで、プレート境界はそれに津波モードを加えたモードで描かれる（`JapanMapGL` の `showOverlayLines`・`showPlateLines`。**`shareCardContent.ts` の判定はこの式と揃えること**）ため、モードと表示設定の両方を見る。プレート境界を津波モードでも描くのは 2026-10-22 ユーザー選択「プレート境界だけ出す (Recommended)」。震源カタログモードでも描いていたのに挙げていなかったのを、同じ時に直した（PB2002 は帰属表示が利用条件。2026-10-24 ユーザー選択「一緒に直す (Recommended)」）。海底地形は設定だけで決まる。公開観測点の印は `App.tsx` が渡す `showPublicStations`（地図へ渡す印が 1 つ以上ある）で決まる。印は、下部に公開観測点の波形を出していればその観測点、出していなければ地震モードで開いた地震カードの観測点（下部を優先。[`map-rendering-spec.md`](map-rendering-spec.md) §15「公開観測点の印」）。

**「加工して作成」は全部に掛けない。** 境界線・区域・活断層・プレート境界は元データを GeoJSON へ変換して使うが、海底地形は配信されるタイルをそのまま描いている。まとめて括ると、加工していないものまで加工したと述べることになる。EarthScope は「加工して作成」の側に入れる（例「出典: 気象庁・EarthScope を加工して作成」。2026-10-15 ユーザー承認）—— 印の位置は EarthScope の観測点情報から作った表を使っていて、CC BY 4.0 が求める「変更を加えた旨」もこの句が担う（[`public-waveform-design.md`](../public-waveform-design.md) §2）。

**地図へ新しいデータのレイヤーを足したら、`shareCard.ts` の `ATTRIBUTION_SOURCES` へ出典を足し、載せる条件も見直すこと。** 出典の実体は各ローダーの冒頭コメント（`utils/activeFaults.ts`・`utils/plateBoundaries.ts` など）。

緊急地震速報を含む場合は、これに加えて注意文を 1 行足す。

**注意文の要否は地図のモードで決めない。** 緊急地震速報の予報円と震源はモードに関わらず描かれるため（`JapanMapGL` の `PsWaveGL` / `EewEpicentersGL`）、モードで判断すると「予報円が写っているのに注意文が無い」画像を作れてしまう。判定は「発報中の緊急地震速報があるか」で行う。

注意文は DM-D.S.S が配布時に求める注意事項をまとめたもの。**「震源に近い場所では間に合わないことがある」を落とさないこと**——精度の話だけを残すと、速報が届く前に揺れが来る場合があるという、行動に直結する留保が伝わらない。

## 5. 撮影の仕組み

### フレームバッファは同期の窓でしか読めない

WebGL のキャンバスは、合成が済むと中身が捨てられる。地図は `preserveDrawingBuffer` を既定の false で初期化しており（`JapanMapGL` の `new maplibregl.Map`）、`render` イベントの同期コールバックを抜けた時点で空になる。

実測では、`render` の中で読むと中身のある画が取れ、300ms 後に読むと 1 色・不透明度 0 の空画像しか返らなかった。

`preserveDrawingBuffer` を true にすればこの制約は消えるが、**Map の初期化オプションなので実行時に切り替えられない**——撮影のたびに地図を作り直すことになり、カスタムレイヤーもデータも積み直しになる。

したがって **`ctx.drawImage(glCanvas, ...)` は `render` コールバックの同期実行中に呼ぶ**。`toBlob()` のような非同期 API へ差し替えると、コールバックを抜けたあとに読むことになり空になる。写し取ったあとの加工（見出し・出典の合成）は 2D キャンバス上の話なので、いくら時間をかけてもよい。

### 寸法の決め方

寸法は 3 つから選ぶ（設定の窓の「共有カードの寸法」。既定は X（16:9）。2026-10-24 ユーザー選択「16:9・1:1・4:5 (Recommended)」・名前は同日「この文面で (Recommended)」）。

| 名前 | 寸法 | 根拠 |
|---|---|---|
| X（16:9） | 1600×900 | 既定。2026-08-30 19:23 JST ユーザー「解像度に関してなのですが、Twitterに合わせてほしいです。今後設定でどのフォーマットに合わせるか選べるようになるといいですね。」、19:29「一応推奨解像度やアスペクト比は調べて決定してほしいです。」。X のタイムラインは横長比率で切り抜く。X の推奨は 1200×675（16:9）で、同じ比率で上回る値を採り、拡大しても文字が読めるようにした |
| 正方形（1:1） | 1080×1080 | 各サービスの公式の推奨は見つからず、寸法の解説サイト（Hootsuite・socialk.it・SocialPilot など）が挙げる値から選んだ。Instagram のフィード（1080×1080）と Bluesky（1200×1200）が共通して挙がる形 |
| 縦長（4:5） | 1080×1350 | 同上（Instagram のフィード・Bluesky がともに 1080×1350） |

- **カード全体をこの比率にする**——地図だけを合わせると、上下に足した見出しと出典が切り抜きで落ちる
- **出力の画素数は寸法に固定する。** 端末の解像度に任せると同じ操作でファイルサイズが数倍に振れ、X のファイルサイズ上限（モバイル 5MB）に触れる。実測で 1600×900 の PNG が 1.4MB

**撮影は端末の解像度のまま高精細に行い、合成で寸法へ縮小する。** 縮小はスーパーサンプリングとして働くので、解像度の高い端末ほど滑らかな画になる。

寸法は `SHARE_CARD_FORMATS` に名前付きで定義してあり、設定の `shareCardFormat` がその識別子を持つ（`useShareCard` が撮影と合成の両方へ同じものを渡す）。**足すときは全体の比率で定義すること**（地図の比率ではない）。

### カードの縦横比でレンダーし直す

撮影は地図コンテナを一時的にカードの縦横比へ広げ、その寸法でレンダーさせてから写し取り、元へ戻す。別の Map インスタンスを立てないのは、レイヤーの登録が `Map/` 配下のコンポーネント十数個に分かれており、二つ目の地図に同じ絵を再現できないため。

**描く寸法は、出力と同じ縦横比のまま、面積を画面の地図領域に揃える**（`renderSizeFor`）。震度の点・地名・線の太さは CSS px で描かれるので、出力寸法（16:9 なら幅 1600）の CSS px で描くと、画面の地図領域が小さい端末ほど記号が画像に対して小さくなる。出力に足りない画素は地図の画素の比率（`setPixelRatio`）で補い、撮った後に端末の解像度へ戻す。重ねる精細さは出力の 2 倍までにする（`MAX_SUPERSAMPLE`）。自前の描画レイヤー（震源の点・予報円・震度0 以下の点）は線の太さ・点の大きさに `map.getPixelRatio()` を掛けるので、この比率に追随する —— `window.devicePixelRatio` を直に読むと、撮影のときだけ小さく描かれる。

**描く寸法は画面の地図領域より大きいことがある。** 地図コンテナの親（`position:absolute` の枠）は overflow を持たないため、広げた分がそのまま隣のパネルへはみ出して見える（実測: 929×454 の地図領域に対し、下のパネルへ 176px かぶさっていた）。撮影中だけ親を切り抜く。

**タイルの読み込みは 8 秒まで待ち、揃わなければ欠けたまま撮る**（`CAPTURE_IDLE_TIMEOUT_MS`。撮れないより撮る）。欠けたまま撮った画像には、その断り書きを焼く（欠けたまま撮ることは 2026-10-23 ユーザー選択「今のまま記録する (Recommended)」）。断り書きの位置は、右下に凡例を焼くので地図の左下。

寸法を変えている間は画面がその寸法で描かれてしまうため、**撮影の直前の画を静止画として被せて隠す**。利用者には地図が一瞬止まったように見える。静止画は親と同じ大きさなので、上の切り抜きが無いと覆いきれない。

### 後始末は 1 つずつ

撮影後の復元（寸法・切り抜き・画素の比率・地図の再計測・カメラ・静止画の除去）は**個別に囲って、1 つ失敗しても残りを実行する**。
素直に並べると途中の 1 行が投げた時点で以降が飛び、とくに静止画の除去に届かないと**地図が撮影直前の画で覆われたままになる**。静止画は `pointer-events: none` なので操作は下の地図へ届くが、その結果が画面に現れない（リロードするまで戻らない）。加えて後始末の中で投げた例外は、撮影で起きていた元の例外を握り潰すため失敗の原因も失われる。

### 追従の目標へ寄せ直す

撮影は寸法を広げた後、**地図の追従が最後に寄せた目標へ、その寸法で寄せ直す**（`beginCaptureFraming`）。撮り終えたら、撮影を始める前のカメラへ戻す。画面の構図のまま撮ると、カードと画面の縦横比が違うぶん、追従が画に入れたもの以外の範囲まで写り込む。

- **目標は `camera.ts` の寄せる関数が、冒頭の共通処理（`beginFit`）で覚える。** カメラを動かすのは `fitJapan`・`flyToPoint`・`flyToBounds`・`flyToBoundsSnapped` の 4 つで（`fitToPositions` はこのどれかへ委ねる）、どの追従（地震カード・EEW・揺れ検知・津波・観測点の行）もここを通るので、目標は同じ場所に残る。寸法待ちで保留した寄せも、目標としては最新
- **利用者が地図を手で動かした後でも、追従の目標へ寄せ直す**（2026-10-25 ユーザー選択「追従の目標へ」）
- **一度も寄せていない地図（起動直後）は日本全体へ寄せ直す**（`fitJapan` と同じ目標）
- 余白と寄り上限は撮影の寸法で決め直す。範囲への寄せで呼び出し側が寄り上限を明示していたときだけ、その値を使う。1 点への寄せは、寄せたときのズームのまま使う
- **着地のズームは段階へ切り下げない。** 切り下げは成長フォローの判定との往復を避けるためのもので、1 枚撮るだけの寄せに当てると最大で半段ぶん引いた画になる
- **撮影の間は、追従の寄せでカメラを動かさない**（`captureSessions`）。タイルを待つ間（最大 8 秒）に追従が寄せると、撮影の寸法のまま飛び始めて構図が崩れる。その間の寄せは目標として覚えたうえで預かり、撮り終えて元のカメラへ戻した後に流す。寸法待ちで保留していた寄せが撮影の寸法変更で走る場合も同じく預かる（そのため、撮影の印は寸法を広げる前に張る）。戻すのに失敗しても、預かった寄せは流す
- **追従が飛んでいる途中で撮ったら、戻した後で最後の寄せをやり直す。** 戻す先が飛行の途中の位置のまま止まらないように
- 寄せ直しも戻しも **`beginProgrammaticFlight` の印を付ける。** 印の無いカメラ操作は手動の操作として扱われ（`ensureUserInteractionState`）、地図の自動追従が `INTERACTION_HOLD_SEC` 秒止まる
- 寄せ先を算出できなければ（算出や寄せ直しのカメラ操作が例外を投げても）、カメラを動かさずに撮り、記録を残す。このとき写るのは、中心とズームは画面のままで、撮影の寸法に広げた範囲
- 撮影が重ならないことは呼び出し側（`useShareCard` の二重起動防止）が保証する

### 凡例も焼く

画面の右下に出している凡例を、画像の同じ位置へ描き足す（`drawLegend`。2026-10-27 ユーザー選択「画像も右下へ揃える (Recommended)」）。画像は単体で流通するので、
色の意味が読めないと震度も等級も伝わらない。**下の津波の観測棒と同じく、地図へ重ねた DOM なので
WebGL のキャンバスには写らない** —— 撮った画像へ 2D で描き直す。

- **中身は画面と同じ組を渡す**（`buildLegendBlocks` の結果。見本の種類は [`map-rendering-spec.md`](map-rendering-spec.md) §20 の表）。設定で凡例を切っているときは
  空配列で、そのときは焼かない —— 画面に無いものを画像へ入れない
- **畳んだ状態は反映しない。** 画像は後から開けないので、常に開いた形で焼く
- **画面側の「狭い画面ではひと段小さくする」も反映しない**（→ [`map-rendering-spec.md`](map-rendering-spec.md) §20）。
  出力は選んだ寸法で固定なので、撮った端末によって画像の中の凡例の大きさが変わるほうが困る
- **地震活動の密度の欄には、期間の行と注記を焼く**（つまみは焼かない。→ [`map-rendering-spec.md`](map-rendering-spec.md) §20「ヒートマップの欄だけは操作を持つ」）。
  寸法の計算と描画は同じ行割り（`legendPeriodLines`）から読む
- **色見本の幅は形ごとに違う**（縦棒は細い）。幅の計測と描画は `legendChipLayout` の 1 つから
  読む —— 別々に持つと、予約した幅と文字の位置がずれて隣の組と重なる
- 何をブロックへ並べるかは [`map-rendering-spec.md`](map-rendering-spec.md) §20 の担当

### 地図キャンバスに写らないもの

津波の観測棒・到達確認マーカー・欠測マーカーは `maplibregl.Marker`（DOM 要素）なので WebGL のキャンバスには含まれない。撮影した 2D キャンバスへ同じ形を描き直す（`gl/tsunamiObsBar.ts` の `drawTsunamiObsBars`・`gl/tsunamiArrivalMarker.ts` の `drawTsunamiArrivalMarkers`・`gl/tsunamiMissingMarker.ts` の `drawTsunamiMissingMarkers`）。形と不透明度はそれぞれ画面側の DOM（`updateBarEl`・`TsunamiArrivalMarkersGL` の `updateMarkerEl`・`TsunamiMissingMarkersGL`）と対応させてある——**片方だけ変えると、画面と画像で見た目がずれる**。対象があるのに 1 つも描けなかったとき（すべて地球の裏側と判定された）は記録を残す。

描き足しは撮影の同期窓の中で行う。`map.project()` が撮影寸法で答える必要があるため、復元後に呼ぶと棒だけ別の場所に立つ。

球投影では `map.project()` が地球の裏側の点にも画面内の座標を返すため（[`map-rendering-spec.md`](map-rendering-spec.md) §6）、投影して戻す往復で手前の面にある点だけを描く。

### 点滅するものは撮影の間だけ止める

津波の海岸線は点滅し、周期（2.5 秒）の 2 割は消灯している。**撮影の間は点灯のまま止める**（`gl/captureMap.ts` の `registerCaptureHold` に `TsunamiLinesGL` が登録し、撮影の始まりで止めて後始末で戻す。2026-10-24 ユーザー選択「ここで一緒に直す (Recommended)」）。止めないと、消灯の間に撮った画像から海岸線が丸ごと消える。止めるのは寸法を広げる前なので、広げた後の描き直しと読み込み待ちに止めた見た目が乗る。

## 6. 共有と保存

**画像と本文を一緒に渡す。** 共有シートから X などを選べば、画像が添付された状態で本文が入る。

`navigator.canShare({ files, text })` が真なら共有シートへ渡し、そうでなければ画像を保存する（保存へ落ちたときの本文の扱いは後述）。共有シートを閉じただけの取り消し（`AbortError`）は失敗ではないので、保存へは落とさずそのまま終える——**クリップボードも書き換えない**。共有をやめた利用者の手元を勝手に上書きしないため。

**判定は渡すものをすべて含めて行う。** 画像だけで `canShare` を確かめて本文を後から足すと、本文を受け取れない実装で `share()` が投げ、そこから保存へ落ちる遠回りになる。

保存名は種別と時刻から作る（例: `quake_20260830_190531+0900.png`）。**種別の語は ASCII に限る**——日本語のファイル名を扱えない環境があるため。

### 本文の中身

**見出しと同じ材料で組み立てる**（`buildShareText`）。画像と本文で違うことを述べないため。

| 行 | 中身 |
|---|---|
| 1 | 見出しと副見出し（例: 「最大震度 5弱　福島県沖　M6.1　深さ 50km」） |
| 2 | 時刻（地震は地震発現時刻・緊急地震速報は地震発生時刻と地震発現時刻・津波は発表）。緊急地震速報では報番号が前に付く（「第3報　地震発生時刻 …　地震発現時刻 …」）。画像の右上と同じ文字列。無ければ行ごと落とす |
| 3 | アプリの URL |

**地震の時刻は、画面のカードと同じ考え方（名前つき・秒なし・「ごろ」なし）で焼く**（2026-10-22 ユーザー承認
「5-A 秒と発生を落とす」・2026-10-23 ユーザー選択「公式名を付ける (Recommended)」。例: `地震発現時刻 2024/01/01 16:10`）。画像は日をまたいで共有されるので年月日まで入れ、
**秒は出さない** —— `earthquake.time` は発現時刻（`ArrivalTime`）が先で電文に秒が無い。以前は
`2024/01/01 16:10:00 発生` と焼いており、**電文に無い `:00` を画像へ残したうえ、発現時刻を「発生」と
名乗っていた**（画像は訂正できない）。

**緊急地震速報はこのまま「… 発生」。** あちらが出すのは `originTime`（地震発生時刻）で、電文が秒まで持つ。

**緊急地震速報の注意文は本文に入れない。** 注意文は画像へ焼いてあり、本文と画像は共有シートで一緒に渡る。本文にも重ねると X の全角 140 字にほぼ届き、震源名が長ければ超える——利用者が削ることになり、削られた結果として注意文そのものが落ちうる。出典を本文へ出さないのも同じ理由。

**DMDSS 版から共有しても standard 版の URL を載せる**（`standardAppUrl`。2026-08-31 15:57 JST ユーザー選択「常に standard 版（推奨）」）。DMDSS 版は DMDATA.JP の API キーが要るため、受け取った人がそのまま開くと設定画面に突き当たる。

### 共有シートを持たない環境

画像を保存し、渡し先の無くなった本文はクリップボードへ置く（`copyToClipboard`）。**置けたかどうかを確かめてからボタンの表示を変える**——置けていないのに「コピーしました」と見せると、利用者は貼り付け先で初めて気づくことになる。

置けない理由は 2 つある。クリップボードの API が無い場合（安全な文脈でない配信）と、書き込みが拒否される場合（クリックからの猶予が切れたときを含む。画像の生成に手間取るとここへ来る）。**置けなかったこともボタンに出す**（「画像を保存しました（本文はコピーできませんでした）」）——記録だけに残すと、本文が入っていないことに貼り付け先で初めて気づくことになる。

**表示を分ける判定に `textCopied` だけを使わない。** 共有シートが応じた場合もクリップボードは使っていないため偽になり、正常系と「置けなかった」が同じ扱いになる。保存へ落ちたとき（`result` が `downloaded`）だけを対象にする。

## 7. 既知の限界

**起動直後に撮ると、過去の電文の取得を巻き込むことがある。** 撮影は撮影の寸法で寄せ直した範囲の地図タイルをまとめて要求するため、その通信が過去の地震の電文取得と競合する。実測（描く寸法を出力寸法にしていたころ。面積を画面に揃えたいまの寸法では測り直していない）では、起動 3 秒後に撮ると電文取得が多数失敗し、履歴が落ち着いた 12 秒後では 1 件も失敗しなかった。取得の失敗は画面の「〇〇を取り込めず」に出るため黙って欠けることはなく、読み込み直せば戻る。

**津波の観測棒・到達確認マーカー・欠測マーカーの見た目は、テストボタンで確かめられる。** 大津波警報テストと変化の小さい続報テストが観測点つきの報を流す（[`settings-pwa-spec.md`](settings-pwa-spec.md) §7）。実電文の並びで確かめるなら過去の地震の再生を使う。
